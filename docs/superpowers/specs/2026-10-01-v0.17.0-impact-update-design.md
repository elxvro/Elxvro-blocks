# ELXVRO Blocks v0.17.0 — Impact Update Design

## Status
Approved in chat for specification on 2026-10-01.

## Goal
Make ELXVRO Blocks feel materially more polished and impactful without destabilizing the existing menus, navigation, scoring rules, save data, or the previously fixed line-clear logic. The update should focus on tactile feedback, audio variety, a new high-intensity mode, and optional Google Play Games integration while preserving offline play.

## Constraints
- Preserve the current blue/gold ELXVRO visual language and existing menu structure.
- Preserve the rule that only completely filled rows and columns are cleared.
- Do not allow visual effects to mutate board state.
- Existing local progress, records, coins, XP, achievements, themes, and settings must remain valid.
- Google Play Games must be optional; the game must remain fully playable offline and when sign-in fails.
- Reuse the existing release-signing/build workflow rather than redesigning CI unless a required dependency makes a minimal change unavoidable.
- Performance mode must reduce expensive visual effects on weaker devices.

## Current State Observed
The v0.16.2 codebase already contains:
- Material-aware game effects and haptics hooks.
- Perfect Clear and live-record effect state.
- Local records, XP, achievements, weekly statistics, and per-mode best scores.
- A three-track non-repeating music playlist with ducking around important effects.
- Existing Classic, Timed, Target, Daily, Zen, and Hard modes.
- Regression-sensitive line-clear behavior after the previous premature-clear bug fix.

The design therefore extends existing systems rather than replacing them.

## Feature 1 — Fracture 2.0
### Behavior
When one or more lines clear, the board engine determines the exact cells to remove. A separate presentation layer receives only those resolved cells and renders impact effects. The effect layer must never decide which cells are cleared.

### Material profiles
- Glass: bright edge flash, narrow shards, high initial velocity, light spin.
- Crystal: sharper refractive fragments, higher sparkle density, slightly longer decay.
- Stone: larger heavy fragments, dust puff, shorter horizontal travel, stronger camera impulse.
- Marble: dense chips, powder dust, slightly slower fall than stone.
- Wood: splinters, medium travel, warm debris, softer impact pulse.
- Leaf: light flakes, wider drift, low gravity, soft motion.

### Multi-line clear
- One line: restrained effect.
- Two lines: broader radial spread and layered sound.
- Three or more lines: stronger contact flash, limited camera shake, music ducking, and wider debris field.
- Performance mode scales down fragment count, trails, and shake amplitude.

### Safety
- Effect coordinates are derived from already-resolved clear cells.
- No effect callback can call board mutation methods.
- Existing board tests remain authoritative for clear eligibility.

## Feature 2 — Brighter Material Rendering
The current blue/gold UI remains unchanged. Block rendering gains stronger material readability through:
- Brighter bevel/specular edges.
- Subtle top-left light direction consistency.
- More visible contact shadows.
- Slight placement pulse/glow.
- Theme-specific highlight behavior.

The background and menu layout are not redesigned.

## Feature 3 — Music 2.0
### Playlist
Expand from three tracks to six calm puzzle-oriented tracks.

### Selection
Use a shuffle-bag strategy:
- Each track appears once per bag.
- A new bag is randomized after all tracks have played.
- The first track of a new bag cannot equal the last track of the previous bag.

### Transitions
- Fade out the current track near completion or before manual transition.
- Fade in the next track.
- Retain existing music ducking for clear tiers, Perfect Clear, rewards, and records.

### Failure handling
If a track fails to load, skip it for the current bag and continue. Retain a fallback path so audio failure never blocks gameplay.

## Feature 4 — Combo Rush Mode
Add a new mode instead of replacing the existing 2-minute Timed mode.

### Rules
- Duration: 120 seconds.
- Each consecutive scoring clear increases the combo chain.
- A placement that does not produce a clear breaks the chain.
- Score receives a combo multiplier using bounded tiers to avoid runaway values.
- The mode stores an independent best score and independent best combo.

### Suggested multiplier tiers
- Combo 0–1: x1.0
- Combo 2: x1.15
- Combo 3: x1.30
- Combo 4: x1.50
- Combo 5+: x1.75 cap

Exact constants may be tuned during implementation if tests reveal balance issues, but the multiplier must remain capped.

### UI
Reuse the existing mode-selection and game HUD components. Add only the minimum labels needed for Combo Rush status and combo visibility.

## Feature 5 — Perfect Clear Upgrade
When the board becomes empty as the direct result of a valid clear:
- Trigger the existing Perfect Clear effect path with a stronger visual layer.
- Grant a defined coin bonus and XP bonus exactly once for that event.
- Play the theme-specific Perfect Clear sound.
- Display a short premium banner.

The reward transaction must be idempotent within the event so animation rebuilds cannot duplicate rewards.

## Feature 6 — New Record Moment
When the current score first exceeds the previous mode record during a round:
- Trigger one celebration per round.
- Show a short gold highlight / banner.
- Play the record cue/fanfare.
- Avoid repeatedly triggering on every later scoring event.

End-of-round score persistence remains the source of truth for the saved record.

## Feature 7 — Google Play Games Integration
### Architecture
Introduce a dedicated `PlayGamesService` boundary. Game screens and `AppState` interact with that service through a small API rather than directly calling platform code.

### Required behavior
- Silent/automatic sign-in attempt where supported.
- Manual retry entry point from the existing leaderboard/profile area if automatic sign-in fails.
- Local gameplay continues regardless of sign-in result.
- Classic best score and Combo Rush best score can be submitted to separate leaderboards.
- Existing local achievements can map to Play Games achievements.
- Failed submissions are non-fatal and retried on later suitable events.

### Local-first rule
Local `AppState` remains authoritative for gameplay progression, coins, XP, unlocked themes, and offline records. Google Play Games is a synchronization/display layer, not a hard dependency.

### Data declaration impact
After the SDK is actually added, Play Console Data Safety and sign-in declarations must be reviewed again before production release.

## Persistence Changes
Add new persisted fields without renaming existing keys:
- Combo Rush best score.
- Combo Rush best combo.
- Optional pending Play Games synchronization flags/values if needed.

Existing keys and save semantics remain intact to avoid migration breakage.

## Testing Strategy
### Board regression tests
- Incomplete row never clears.
- Incomplete column never clears.
- Only completed rows/columns clear.
- Simultaneous row + column clear removes only the union of completed cells.
- Visual effect state cannot trigger extra board clears.

### Combo Rush tests
- Timer starts at 120 seconds.
- Combo increments only after scoring clears.
- Non-clearing placement resets combo.
- Multiplier follows capped tiers.
- Best score and best combo persist independently.

### Reward tests
- Perfect Clear reward granted once per event.
- Record celebration fires once per round.

### Audio tests
- Shuffle bag does not repeat a track before the bag is exhausted.
- First track of a new bag differs from the prior bag's last track when more than one track is available.
- Disabled music and lifecycle pause/resume remain functional.

### Play Games tests
- Game starts and plays with no Play Games connection.
- Sign-in failure is non-fatal.
- Successful score submission uses the correct leaderboard target.
- Duplicate synchronization does not corrupt local state.

### Build verification
Before release claim:
- `flutter analyze`
- `flutter test`
- Release signed APK build
- Release signed AAB build
- Artifact upload verification

## Release Target
- Marketing version: `0.17.0`
- Android versionCode: next unused code after v0.16.2+35.
- Deliverables: signed APK, Google Play AAB, and a ZIP containing both.

## Non-Goals
- No menu/navigation redesign.
- No replacement of the board engine.
- No cloud-save system in this update.
- No ads or monetization SDK in this update.
- No mandatory Google account gate.
- No destructive save migration.

## Acceptance Criteria
The update is complete only when:
1. Existing screens and navigation remain present and functional.
2. Incomplete lines never clear in regression tests.
3. Material-specific clear effects are visibly differentiated.
4. Music no longer behaves like a small repeating loop and uses the six-track shuffle-bag design.
5. Combo Rush functions as a separate 120-second mode with its own records.
6. Perfect Clear and new-record moments are stronger without duplicating rewards/events.
7. The game remains fully playable offline and when Play Games sign-in fails.
8. Analyze/tests pass and signed APK+AAB are produced successfully.
