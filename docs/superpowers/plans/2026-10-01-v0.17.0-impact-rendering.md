# ELXVRO Blocks v0.17.0 Impact Rendering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Fracture 2.0, brighter material rendering, stronger Perfect Clear feedback, and a one-shot premium new-record moment without changing board-clear rules.

**Architecture:** `BoardEngine` remains the sole authority that mutates board state. A new deterministic fracture-presentation model consumes only `PlacementResult.clearedCells`; `GameScreen` renders those specs and never derives additional clear cells. Existing `ThemedBlockTile`, Perfect Clear state, and record state are extended instead of replacing menus or navigation.

**Tech Stack:** Flutter 3.47.4, Dart, `CustomPainter`, `SharedPreferences`, `flutter_test`.

**Spec:** `docs/superpowers/specs/2026-10-01-v0.17.0-impact-update-design.md`

## Global Constraints

- Preserve the current blue/gold ELXVRO visual language and existing menu structure.
- Preserve the rule that only completely filled rows and columns are cleared during normal-piece play.
- Do not allow visual effects to mutate board state.
- Existing local progress, records, coins, XP, achievements, themes, and settings must remain valid.
- Performance mode must reduce expensive visual effects on weaker devices.
- Perfect Clear bonus is exactly **+75 coins and +120 XP** per valid Perfect Clear event.
- New-record celebration fires at most once per round.

## Review Focus

- Simultaneous row + column completion must clear only the union of completed cells, with the crossing cell counted once; pinned in Task 1.
- A special-piece result may visually fracture its returned `clearedCells`, but presentation code must not expand the set; pinned in Task 2.
- Performance mode must reduce particle count/shake but keep visible feedback; pinned in Task 2.
- An empty `clearedCells` list must create no fracture burst and no Perfect Clear bonus; pinned in Tasks 2 and 4.
- Crossing the previous record multiple times in one round must still fire one celebration; pinned in Task 4.

### Task 2: Add Deterministic Fracture 2.0 Presentation Model

**Files:**
- Create: `source_snapshot/lib/effects/fracture_effect.dart`
- Create: `source_snapshot/test/fracture_effect_test.dart`
- Modify: `source_snapshot/lib/screens/game_screen.dart`

**Interfaces:**
- Consumes: `List<BoardCell> clearedCells`, `ThemeMaterial material`, line count, performance-mode flag.
- Produces: `FractureBurst buildFractureBurst({required List<BoardCell> clearedCells, required ThemeMaterial material, required int lineCount, required bool performanceMode, required int seed})`.
- Produces: `FractureBurst` with `List<FractureParticleSpec> particles`, `double flashStrength`, and `double shakeAmplitude`.
- Produces: each `FractureParticleSpec` contains the source `BoardCell cell`, normalized offsets/velocity, rotation/spin, size, lifetime, and `FractureShape`.

- [ ] **Step 1: Write the failing fracture tests**

Test that an empty cell list returns an empty particle list and zero shake; every generated particle references one of the supplied cells; glass/crystal use smaller sharper shapes than stone/marble; leaf has lower gravity/longer drift; and `performanceMode: true` produces fewer particles and lower shake than false for the same seeded input.

- [ ] **Step 2: Run the fracture tests and verify failure**

Run: `flutter test source_snapshot/test/fracture_effect_test.dart`
Expected: FAIL because `fracture_effect.dart` does not exist.

- [ ] **Step 3: Implement `fracture_effect.dart`**

Use `Random(seed)` so tests are deterministic. Particle generation must iterate only over the supplied `clearedCells`; it must not inspect or mutate `BoardEngine.grid`. Material profiles: glass/crystal = narrow shards/high velocity; stone/marble = large chips/high gravity; wood = splinters; leaf = light flakes/low gravity. Cap total particles to 180 normally and 72 in performance mode.

- [ ] **Step 4: Integrate the burst into `GameScreen`**

When `BoardEngine.place` returns a result with `clearedCells.isNotEmpty`, call `buildFractureBurst(...)` using the active theme and the resolved result. Replace/bridge the current clear-particle setup with the returned specs. Camera impulse and contact flash use only `FractureBurst.shakeAmplitude` and `.flashStrength`; no callback from the effect layer may call `place`, `restore`, `reset`, or edit `grid`.
