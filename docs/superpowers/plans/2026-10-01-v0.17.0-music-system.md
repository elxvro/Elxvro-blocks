# ELXVRO Blocks v0.17.0 Music System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the small-loop feel with a six-track CC0 shuffle-bag playlist, smooth transitions, and preserved ducking/lifecycle behavior.

**Architecture:** Extract track ordering into a pure deterministic `MusicShuffleBag` class so repeat prevention is independently testable. `AudioService` keeps ownership of actual playback and gains a transition gain layered with the existing music volume and ducking factor.

**Tech Stack:** Flutter 3.47.4, Dart, `audioplayers` 6.8.1, `flutter_test`, FFmpeg in GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-01-v0.17.0-impact-update-design.md`

## Global Constraints

- Keep existing music/sfx/ui toggles and volume persistence unchanged.
- Preserve pause/resume behavior across app lifecycle events.
- Retain existing music ducking for clear tiers, Perfect Clear, rewards, and records.
- A failed music asset must not block gameplay.
- Use six CC0/public-domain tracks only.
- Do not alter menu structure.

## Review Focus

- No track may repeat before the current bag is exhausted; pinned in Task 1.
- The first track of a new bag must differ from the previous bag’s last track when the list has more than one item; pinned in Task 1.
- A failed track must be skipped for the current bag rather than retried forever; pinned in Task 2.
- Ducking and transition gain must multiply rather than overwrite each other; pinned in Task 2.
- Disabling music during a fade must leave the player paused/stopped, not restart the next track; pinned in Task 2.
