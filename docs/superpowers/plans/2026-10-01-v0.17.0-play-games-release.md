# ELXVRO Blocks v0.17.0 Play Games and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add optional real Google Play Games authentication/leaderboards/achievement sync, then ship v0.17.0 as signed APK + AAB without making Play Games a gameplay dependency.

**Architecture:** Keep `SocialService` as the app-facing boundary and add a `PlayGamesService` implementation backed by `games_services`. Platform IDs are isolated in one configuration object; empty IDs disable remote actions gracefully. The release workflow is cloned from the proven v0.16.2 workflow and changes only version/source/test/audio/Play Games setup needed by v0.17.0.

**Tech Stack:** Flutter 3.47.4, Dart, `games_services` **5.0.0**, `SharedPreferences`, GitHub Actions, Java 17, FFmpeg, Android Play Games Services v2.

**Spec:** `docs/superpowers/specs/2026-10-01-v0.17.0-impact-update-design.md`

## Global Constraints

- Google Play Games is optional; sign-in/configuration failure must never block local gameplay.
- Local `AppState` remains authoritative for coins, XP, themes, achievements, and offline records.
- Classic and Combo Rush submit to separate leaderboards.
- Existing local achievements map to Play Games achievements when configured.
- Preserve package name `com.elxvro.elxvro_blocks` and existing signing secrets/workflow pattern.
- Release target is `0.17.0+36` unless Play Console shows versionCode 36 has already been used; if used, increment to the next unused code without changing marketing version.
- Deliver signed APK, Google Play AAB, and one ZIP containing both.
- No ads/AD_ID integration in this release.

## Review Focus

- Missing Play Games app/project ID must degrade to local-only behavior, not crash startup; pinned in Tasks 2 and 4.
- Missing one leaderboard/achievement ID must skip only that remote action, not all Play Games features; pinned in Task 2.
- Duplicate score/achievement sync attempts must not alter local progress or throw into gameplay; pinned in Task 3.
- A sign-in failure or no network must keep Leadership Center usable with local records; pinned in Task 3.
- Release artifacts must be signed by the same configured release keystore path as v0.16.2 and both APK/AAB must exist before artifact upload; pinned in Task 4.

## External Play Console Gate

The code and signed build can operate in local-only mode with no Play Games configuration. Before advertising Google Play Games as active in the production listing, Google Play Console must contain the game project, OAuth credential for package `com.elxvro.elxvro_blocks` with the release signing certificate, the Classic and Combo Rush leaderboards, and the mapped achievement IDs; then populate the app/project ID and Dart ID configuration used by the build.
